## Dev-Build-Anleitung (Skia und MMKV laufen nicht in Expo Go)

Einmalig:

1. Konto auf https://expo.dev anlegen (kostenlos).
2. Auf dem Rechner Node 22 installieren, Repo klonen, im Repo `npm install`.
3. `npm install -g eas-cli`, dann `eas login`.
4. `eas init` verknüpft das Projekt mit deinem Konto (schreibt eine `projectId` in `app.json`; diese Änderung bitte als kleinen PR committen oder dem Leiter geben).

Android (am einfachsten):

5. `eas build --profile development --platform android`. Läuft in der Expo-Cloud, dauert ca. 10 bis 20 Minuten.
6. Am Ende zeigt die Konsole einen Link und QR-Code. Auf dem Handy öffnen, APK laden, Installation aus unbekannten Quellen erlauben, installieren.

iOS:

5. Apple-Developer-Konto nötig (99 €/Jahr). `eas device:create` und den Link auf dem iPhone öffnen, um das Gerät zu registrieren.
6. `eas build --profile development --platform ios`, danach über den Link installieren. Auf dem iPhone Entwicklermodus aktivieren (Einstellungen > Datenschutz & Sicherheit > Entwicklermodus).

Täglich:

7. Am Rechner im Repo `npx expo start` (Handy und Rechner im selben WLAN, sonst `npx expo start --tunnel`).
8. Die installierte PotPou-Dev-App öffnen und den QR-Code scannen. JS-Änderungen laden ohne neuen Build.
9. Neuer Build ist nur nötig, wenn ein Auftrag ein natives Paket hinzufügt (steht dann in dessen Progress-Notiz).

## Entscheidungen

- Tabs direkt in `app/_layout.tsx`, keine `(tabs)`-Gruppe, damit die Pfade aus `AUFTRAEGE.md` stimmen. Screens ohne Tab haben `href: null` und keine Tab-Leiste. `backBehavior="history"`, damit "Zurück" funktioniert.
- Expo Router 58: `Tabs` aus `expo-router/js-tabs`, `Stack` aus `expo-router/stack`, `SplashScreen` aus `expo-router`.
- Slices sehen nur ihren eigenen Zustand (`SliceCreator<T>` in `src/store/slices/types.ts`). Registrierung: Import plus eine Zeile im Objekt `slices`. Zugriff auf andere Slices über `useGameStore.getState()` in Hooks oder Spiellogik.
- `GameState` ergibt sich automatisch aus allen registrierten Slices.
- Einstellungs-Abschnitte: Liste in `src/components/settings/sections.ts` (statt direkt in `app/settings.tsx`), eine Zeile je Abschnitt. Der "Entwicklung"-Abschnitt (`DevLinksSection.tsx`) kann von P09 übernommen werden.
- NativeWind-Klassen nutzen die Palettennamen (`bg-cream`, `text-ink`, `font-heading`, `font-body-bold`).
- Bundle-ID / Package vorläufig `app.potpou` in `app.json`. Muss der Chef vor dem ersten Store-Build festlegen.
- `CareActionId` in `events.ts`: `water`, `fertilize`, `pet`. P04 ergänzt bei Bedarf.
