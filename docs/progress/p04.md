## Entscheidungen

- API-Signaturen (für P10, P13, P15, P05):
  - `computeNeeds(state, nowMs, modifiers, phase)`: `phase` ist ein vierter Parameter, weil Sämling und Trocknen anders abfallen. Die Phase liefert `getPlantStatus(plant, nowMs).phase`.
  - `applyCare(state, action, nowMs, modifiers?)` mit `action = { type: CareActionId, phase, amount? }`. `amount` überschreibt `CARE_AMOUNTS` (für Minigames, P13: max. +40 laut deren Abschnitt).
  - `deriveCondition(snapshot, phase)` nimmt das Ergebnis von `computeNeeds`.
  - `modifiers` = Abfall-Multiplikatoren je Balken (`{ water: 0.8 }` = 20 % langsamer). P15 reicht sie an `computeNeeds` und `care` durch.
- Im Koma ändert `applyCare` nichts (gibt denselben Zustand zurück, Slice meldet `false`, kein Ereignis). Raus nur per `reviveFromComa`; Kosten prüft P05 als Aufrufer (Lina informiert).
- `pet` füllt die Laune; Minigames nutzen `care({ type: 'pet', phase, amount })` oder ergänzen eine eigene `CareActionId`.
